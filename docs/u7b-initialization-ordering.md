# 绝妖星 P1 初始化顺序补偿

当地图 1363 的场景物件尚未同步到 Host 时，Triggernometry 2.2 的 `111/019D`
转换会生成 BaseId 为 0 的 `1019D`。U7b v1.0.5 的原始初始化条件要求
BaseId 2015156，因此这一事件无法进入 P11a；后续冰火与散摊事件也无法生成绘图。
独立 Host 中，物件延后 50 ms 的输入可复现此问题。50 ms 是测试安排，不是阈值；
尚未取得此前实际失败场次的完整日志，不能断言所有缺圈都由此造成。

Host 仅在上述地图遇到物件缺失或 BNpcID 尚未就绪的 `111/019D` 时，暂存
Triggernometry 的原始日志及其后续事件。全量快照或有效实体增量到达后，按顺序交给
原版转换器。其他 ACT 扩展继续正常接收日志，原 XML、条件、动作和绘图参数均保留。

TN 的事件线程和动作线程是两个队列。集中释放积压日志会让冰火条件早于初始化动作
执行。因此，恢复的 P1 初始化还需等待原动作 `UnsetRegexUniversal ^U7b11a`
完成；以插件实例、原事件时间及物件 ID 匹配完成信号，再释放后续日志。
观察器异常不向上游动作线程传播。未命中初始化条件或用户禁用该条目时也不会无限等待。

等待总上限为 500 ms，队列最多 1024 条 / 1048576 个字符。到期或超限时，一次性
按原顺序放行，不补发、不去重；这是回退到原行为，不能修复永久缺失的物件。
切地图、撤销日志权限或卸载插件会清理待处理内容。物件已经就绪、导入日志、
其他地图及旧版转换 ABI 保持原路径。
